# Mekiki Script Guide

This guide is for readers writing a Mekiki script, or a [Rhai](https://rhai.rs/) script of any kind, for the first time. It starts from the very basics.

The complete list of functions and arguments is the [Rhai API reference](../api/generated/rhai-api.md),
generated from the canonical API catalog (`api/rhai-api.toml`). Consult the reference when you move on to advanced use.

## 1. Running a script

- **From the IDE**: open the script and press the Run button on the toolbar.
  `print()` output and errors appear in the log pane. See the [IDE User Guide](ide-guide.md) for how to use it.
- **From the command line**: run `mekiki run script.rhai`.

Pressing `Shift+Alt+C` while a script runs stops it, even when the IDE window is not active.

## 2. Your first script

With Notepad open, run these four lines.

```rhai
let win = expect_window("exe=notepad.exe").to_appear(10000); // wait up to 10 s for Notepad to appear
win.type_text("Hello from Mekiki");                          // bring Notepad to the front and type
win.press("ctrl+s");                                         // open the Save dialog
expect_window("Save As").to_appear(5000);                    // confirm that the dialog appeared
```

These four lines contain the whole skeleton of a Mekiki script.

1. **Find a window and assign it to a variable.** `expect_window(...)` waits until a window matching the
   condition appears and returns it. `let win = ...` declares the variable and assigns it in one step.
2. **Act on that window.** Append `.action()` to the variable, as in `win.type_text(...)` or `win.press(...)`.
3. **Verify the result.** `expect_window(...).to_appear(...)` stops with an error unless the expected state
   is reached. The script records "success was verified", not "it probably worked".

## 3. The minimum Rhai you need to know

```rhai
// A line starting with // is a comment and is not executed

let name = "Yamada";               // a variable; strings are enclosed in " "
let count = 3;                     // a number
let total = count * 2 + 1;         // an expression

print(`Hello, ${name}`);           // ` ` lets you embed variables with ${}
print(total);                      // shown in the IDE log pane

if total > 5 {                     // a condition
    print("many");
} else {
    print("few");
}

for i in 0..3 {                    // repeats with 0, 1, 2
    print(i);
}
for item in ["apple", "orange"] {  // iterate over an array
    print(item);
}

fn greet(who) {                    // a function; groups repeated steps
    print(`Hi, ${who}`);
}
greet("Tanaka");
```

- End each statement with `;`.
- A failed operation stops the script with an error. Where you do not want that, wrap the code in the
  exception-handling form `try { ... } catch (e) { ... }`. `e` holds the error.

```rhai
try {
    win.target("ocr:Update available").click();
} catch (e) {
    print("no update notice appeared; carrying on");
}
```

## 4. Pointing at things: locators

The string inside `target("...")` is called a **locator**. Instead of writing coordinates, you write
*what to look for*. That is the core idea of Mekiki. There are three ways to look.

| Method | Syntax | Suited to |
|---|---|---|
| Image | `"ok.png"` or `"image:ok.png"` | Icons and anything else that has neither text nor a name |
| Text on screen (OCR) | `"ocr:Save"` | Buttons and labels whose text is visible |
| UI element (accessibility data) | `"ui:Save"` / `"ui:name=Save,type=button"` / `"ui:id=saveButton"` | Buttons and input fields of ordinary Windows applications; survives visual changes |

There are also `"point:100,200"`, which names a coordinate directly, and `"region:0,0,800,600"`, which
names a rectangle. Coordinates are absolute screen coordinates. Treat them as a last resort.

**When in doubt, try `ui:`, then `ocr:`, then an image.** `ui:` keeps working across theme and DPI
changes, and works even where screen capture is unavailable.

### Where image files go

- Put them in the same folder as the script and refer to them by file name (`"ok.png"`). A subfolder is
  written as `"buttons/ok.png"`.
- Images imported with the IDE's Paste button go into the `.mekiki/images` folder and are referenced by
  content hash as `"image:sha256:..."`. Giving one a name moves it into the script's folder.
- Absolute paths (`"C:\\shots\\ok.png"`) also work.

### Finding `ui:` names and types

To use `ui:` you need the names and types the application exposes. Run the following script once and copy
from the list in the log.

```rhai
let win = window("exe=notepad.exe");
for item in win.list_ui() {
    print(item);          // printed as ui:name=...,id=...,type=...
}
```

`type=` accepts these 16 kinds.

```text
button  checkbox  combobox  edit  hyperlink  image  list  listitem
menuitem  radiobutton  tab  tabitem  text  tree  treeitem  window
```

On Japanese Windows, button names carry an accelerator such as `保存(S)`. `ui:name=保存` matches either
form, so you can leave the `(S)` out.

## 5. Narrowing the search to a window

Most operations first take a window and then search inside it. That is faster than searching the whole
screen, and it stops you from pressing the same button in another window behind it.

```rhai
let win = window("exe=notepad.exe");            // take the window right now (error if absent)
let win = expect_window("exe=notepad.exe").to_appear(10000); // wait for it (use this right after launch)

win.target("ocr:Save").click();                  // search inside win only
```

| Selector | Syntax | Matches |
|---|---|---|
| Part of the title | `window("Notepad")` | Title contains "Notepad" |
| Executable name | `window("exe=notepad.exe")` | **Usually this.** Keeps working when the title changes with the open file |
| Exact title | `window("title_exact=Calculator")` | The whole title matches |
| Title pattern | `window("title=Minutes*")` | `*` is zero or more characters, `?` exactly one |
| Several conditions | `window("exe=notepad.exe,title=Minutes*")` | All conditions hold |
| Window class | `window("class=Notepad")` | Class name starts with `Notepad` |
| Process ID | `window("pid=1234")` | Windows of that process |

Some Windows apps such as Calculator and Settings share `ApplicationFrameHost.exe`, so `exe=` cannot tell
them apart. Name those by title, as in `title_exact=Calculator`.

`win.activate()` brings a window to the front. `win.type_text()` and `win.press()` do that automatically
before typing, so you rarely need to call it yourself.

## 6. Acting

Append the action to `target(...)`. Every action waits automatically until the target has **appeared and
stopped moving** before it runs. The default wait is 3 seconds.

```rhai
win.target("ui:name=Save,type=button").click();      // click
win.target("ocr:File").double_click();                // double-click
win.target("ocr:File").right_click();                 // right-click
win.target("ui:type=edit").type_text("report.txt");   // click, then type
win.target("ui:type=edit").press("ctrl+a");           // press keys over the target
win.target("ocr:List").scroll(0, -3);                 // scroll over the target (negative = down)
win.target("file.png").drag_to(win.target("folder.png")); // drag
win.target("ocr:Help").hover();                       // just move the mouse there
```

You can also type into a window directly. This brings the window to the front and types wherever the
keyboard focus is at that moment. It does not click.

```rhai
win.type_text("Body text goes here");
win.press("ctrl+s");
```

Key combinations join modifier keys and a key name with `+`: `ctrl+s`, `shift+alt+c`, `enter`, `tab`,
`escape`, `f5`, `alt+f4`, and so on. To enter text, use `type_text` rather than keys. It is independent
of the keyboard layout, and Japanese can be typed as it is.

### Things to watch when typing

- Line breaks inside `type_text` are sent as Enter and tabs as Tab.
- Where the text lands depends on the focus at that moment. A notification or another window finishing
  its startup can move the focus, so always name the recipient, as in `win.type_text()` or
  `target(...).type_text()`. Avoid the bare `type_text("...")`, which names no recipient.
- If a window is blocked by its own dialog, the input fails with an error naming the dialog. Target the
  dialog instead.
- After typing anything important, read it back with `read_value` or `read_text`. Windows 11 Notepad can
  drop characters even at the default typing speed.

## 7. Waiting and verifying

"Wait for the job with `sleep(3000)`" breaks on a slow day. Wait for a **visible result** instead.

```rhai
expect(win.target("ocr:Saved")).to_appear(5000);               // wait for it to appear (error if not)
expect(win.target("ocr:Processing")).to_vanish(30000);          // wait for it to disappear
expect(win.target("ui:type=listitem")).to_have_count_at_least(1, 5000); // wait for at least one item

let win = expect_window("exe=app.exe").to_appear(10000);       // wait for a window to appear
expect_window("title_exact=Progress").to_vanish(60000);         // wait for a window to close
```

- Passing `0` for the milliseconds uses the default wait.
- `to_appear` returns the position found (a Match), so you can `.click()` it directly.
- To look exactly once and get true or false, use `t.exists()`. It does not wait.
- Only for jobs that take minutes, combine `exists()` and `sleep()` and poll at your own pace. `expect`
  retries every 333 milliseconds with a full screen search, which is unsuited to long waits.

```rhai
let done = win.target("ocr:Done");
let waited = 0;
while !done.exists() {
    if waited >= 600000 { throw "not done after 10 minutes"; }
    sleep(2000);
    waited += 2000;
}
```

## 8. Reading from the screen

```rhai
let lines = win.read_text();                       // array of OCR lines, in reading order
let value = win.read_value("ui:id=amountBox");     // value of an input field via UI data (not password fields)
let text = clipboard();                            // clipboard text
set_clipboard("text to paste");

let m = win.find("ocr:Total");                     // one position (error if absent)
print(`${m.x}, ${m.y}, ${m.width}x${m.height}, score=${m.score}`);
let all = win.find_all("ui:type=listitem");        // all of them (empty array if none)
print(all.len());
```

**A Match returned by `find` or `to_appear` is a record of coordinates at that moment.** It goes stale
when the screen changes, so do not carry one across a screen transition; search again when you need it.

## 9. When there are several of the same thing

```rhai
win.target("ui:type=button").first().click();                  // first in reading order
win.target("ui:type=button").last().click();                   // last in reading order
win.target("ui:type=button").nth(2).click();                   // third in reading order (counted from 0)
win.target("icon.png").best().click();                         // the closest match

win.target("ui:name=Open,type=button").right_of("ocr:Customer A", 300).click(); // within 300 px right of "Customer A"
win.target("ui:type=edit").below("ocr:Name", 100).type_text("Yamada");        // within 100 px below "Name"
```

The reference (anchor) for `right_of`, `left_of`, `above`, `below`, and `near` is an `ocr:` locator or an
image. Naming a target by its position relative to a label survives reordering; `nth` does not.

Listing alternatives for the same purpose tries the next one when the previous is not found. Put the most
stable and cheapest first.

```rhai
win.target("ui:name=Save,type=button").or("ocr:Save").or("save.png").click();
```

## 10. Applications that use a software cursor

In applications that draw their own cursor, such as games, the re-search that every action performs just
before acting (enabled by default) is defeated by the cursor itself, and the action fails.
For such applications, disable the re-search with the API below. You can re-enable it for individual
targets.

```rhai
set_recheck(false);
let ok = win.target("ok.png");
ok.hover();               // searches here
ok.click();               // does not search again; presses where hover found it

win.target("ocr:Next").recheck(true).click();   // this target alone searches again
```

Next, the pointer speed. The default is a conservative value chosen for stability with software-cursor
applications (see "Defaults and settings" in the
[Rhai API reference](../api/generated/rhai-api.md) for the actual number).
Even so, in applications with a low frame rate the cursor's position and the actual action coordinates can
drift apart. In that case, adjust the speed while watching how the application responds.

```rhai
set_move_speed(600);      // slower, for applications that follow the pointer slowly
set_move_speed(2400);     // faster: 2400 pixels per second
set_move_speed(0);        // skip the movement and jump instantly
```

Ordinary Windows applications are generally fine with `0` (instant movement). Where you operate menus or
tooltips that open in response to the pointer arriving, it is safer to leave the default.

## 11. When it does not work

**Read the error message.** When an image or text is not found, the log shows something like this.

```text
'ok_button.png' not found in 3840x2160+0+0 (required 0.70 / best 0.61 / waited 3.0s)
  diagnostic files: ...-screen.png, ...-heatmap.png, ...-annotated.png, ...-candidates.txt
```

- `required` is the similarity needed; `best` is the similarity of the closest thing on screen. If they
  are close, recapture the image or lower the threshold with `.similar(0.6)`. If they are far apart, you
  are looking at a different screen or window.
- The diagnostic files hold the screen at that moment, the similarity distribution, and the candidate
  positions.

**Check what was found**

```rhai
win.target("ocr:Save").highlight(1000);   // outline the match for one second
win.save("evidence.png");                 // save the window as an image
```

**Tuning parameters**

| Symptom | Remedy |
|---|---|
| Takes more than 3 seconds to find | Add `.timeout(10000)`; for the whole script, `set_timeout(10000)` |
| Image not found | `.similar(0.6)`; the default is 0.7. Recapture the image first |
| Never settles because the display is animated | `.force()` skips the wait for stillness |
| The next target is not found right after a click | Wait for the previous action's result with `expect(...).to_appear(...)` first |
| The app ignores short clicks | `set_click_hold(80)` |
| Characters are dropped | `set_type_interval(50)` lengthens the pause between characters |
| Pointer movement is slow and the whole run takes long | `set_move_speed(2400)` raises the speed (see the previous section) |
| The re-search before `click` right after `hover` wastes time | `set_recheck(false)` reuses the previous search result (see the previous section) |

Settings are changed with `set_...()` and last only for that run of the script. There is no function to
read them back, so to restore a value, set the original value yourself.

**Restrictions imposed by applications**

Some games and similar applications use anti-cheat mechanisms that refuse all injected mouse and keyboard
input. Write a short script first to confirm that external control is allowed.

## 12. Habits of a robust script

- Search inside a window, not the whole screen.
- Point by name, type, and position relative to a label, not by coordinates or ordinal position.
- Wait for "the result appeared" with `expect`, not with `sleep`.
- Do not use a uniform area (a plain white square, say) as an image. A featureless image matches anywhere.
- Do not reuse a found position (Match) after a screen transition.
- Always name the recipient of input (a window or a target).
- Do not blindly swallow errors with `try`; write proper error handling.

## Appendix: cheat sheet

```rhai
// Windows
let win = window("exe=app.exe");                               // right now
let win = expect_window("exe=app.exe").to_appear(10000);       // wait for it
win.activate();

// Targets
win.target("ok.png")  win.target("ocr:Save")  win.target("ui:name=Save,type=button")
win.target("point:100,200")  win.target("region:0,0,800,600")

// Actions
.click()  .double_click()  .right_click()  .middle_click()  .hover()
.type_text("text")  .press("ctrl+s")  .scroll(0, -3)  .drag_to(win.target("b.png"))
win.type_text("text")  win.press("enter")

// Narrowing
.first()  .last()  .nth(i)  .best()  .or("ocr:Save")  .similar(0.8)  .timeout(5000)  .force()
.right_of("ocr:Label", 200)  .left_of(...)  .above(...)  .below(...)  .near(...)

// Waiting and verifying
expect(t).to_appear(ms)  .to_vanish(ms)  .to_have_count(n, ms)  .to_have_count_at_least(n, ms)
expect_window("...").to_appear(ms)  .to_vanish(ms)
t.exists()  t.wait_vanish(ms)  sleep(ms)

// Reading
win.read_text()  win.read_value("ui:id=x")  win.list_ui()  clipboard()  set_clipboard("...")
win.find("...")  win.find_all("...")   // Match: x y width height center_x center_y score

// Looking and recording
t.highlight(1000)  win.save("shot.png")  print("...")

// Settings (for this run only)
set_timeout(ms)  set_similarity(0.7)  set_type_interval(ms)  set_click_hold(ms)
set_move_speed(px_per_sec)  set_recheck(bool)  t.recheck(bool)
```
